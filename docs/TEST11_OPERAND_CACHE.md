# Test11 operand validation cache

Private 0.1.2-test11/code46. This build optimizes host interpreter work; it does not add game AOT coverage or establish an Android FPS gain.

The Test10 phone log at4x showed meaningful sampled time in engine fallback and lookup, despite fallback accounting for only about4.9percent of sampled retired instructions after startup. Timing overhead and unclassified work preclude treating those times as exact CPU percentages. Last ten phone windows averaged18.48FPS/61.64percent speed, with no Surface.Download waits.

HasUnpredictableOperands depends exclusively on immutable decoded Instruction fields. Test11 stores its boolean result alongside the decoded instruction on cache misses and reuses it on hits. The shared StepDecodedImpl preserves condition checking before rejecting cached invalid operands, including undefined-instruction behavior. StepDecoded's public signature and semantics remain intact; direct uncached callers continue to compute legality normally. Register values, flags, PC advancement, memory access, alignment/value-dependent checks, exclusive state and stop handling stay live. ARM/Thumb mode and live fetched word remain the cache key. Changed code, remapping and Thumb halfword faults retain fresh-fetch behavior. A miss can perform extra pure checking for a condition-failed instruction; savings depend on cache hit rate and operation mix.

All ten game/driver libraries are reused byte-identically fromTest10. No runtime/context ABI used by generated libraries changes. Required GPU waits, frame production, resolution and guest clocks are preserved. Test10 CPU/graphics diagnostic flags remain enabled for comparison; both options are defaultOFF in source.

Validation includes80000 seeded ARM/Thumb differential executions comparing registers, CPSR, floating-point/exclusive state and the full mapped code/data page against ordinary execution. Explicit tests alternate condition-failed and condition-passed invalid ADDEQS-PC instructions using the same cached word. Changed words, PC reuse, Thumb page crossing, missing second halfword, remapping, engine budgets and SVC stops remain covered. Tests run against the prior generic interpreter objects and then against freshly compiled current objects. Engine main/module/digest-mismatch/fetch-fault and sampling tests, screen/menu regressions and signed package checks are also required.
